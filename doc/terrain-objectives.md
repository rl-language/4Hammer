## User-approved abstraction

The user explicitly requested terrain **areas only**, always at least physical visibility, and partial obscuration when a sight line crosses terrain. The implementation uses the segment between model centres in the horizontal plane: intersecting an area, including its boundary or an endpoint, gives partial obscuration. This is a simulation approximation supplied by the user, not printed line-of-sight geometry. It does not create complete physical occlusion. Hidden remains a separate detection restriction.

Physical features, silhouette tests, enclosed Solid openings, upper surfaces and feature-specific traversal are deferred by that instruction. Existing task-4 solid-box geometry remains available but is not expanded into terrain features here. Area footprints themselves do not obstruct movement. No mission layout or physical terrain was invented.

## Implemented behavior

- Up to 16 bounded rectangular areas have whole-quad corners on the ground plane and independent Exposed/Light/Dense flags. Mixed categories are permitted. Model membership uses any part of its supported circular base; unsupported footprints fail the membership query. There is no invented height limit on area membership.
- Cover is assessed from each attacking model. Every target model must either qualify individually as Infantry/Beasts/Swarm within an area, or be partially obscured by an area crossing. Different members can qualify for different reasons. Unit-wide keyword inheritance does not grant individual model eligibility. Cover worsens ranged BS by one; it changes neither saves nor the hit-roll modifier. Melee/no-hit-roll skill is unchanged. Ignores Cover checks ability presence, including parameterless rules, rather than treating a zero parameter as absence.
- A qualifying model in a Dense area is Hidden if its unit made no ranged attacks this turn or the previous turn. Never-fired history is handled separately from an actual previous turn. Detection defaults to inclusive 15 inches, measured base to base, with an explicit range-override helper for supplied rules. A unit is visible if any member is visible to any observer; per-model weapon selection checks its own observer. Empty units are not visible.
- Shooting and Overwatch selectors reject wholly undetected Hidden targets. A real ranged attack records history even when it misses; selecting a unit and skipping its weapons does not. Existing attack iteration and full shooting-mode rules remain tasks 9/12.
- Four configurable objective points retain the existing editor capacity. A point inside one area links to that entire terrain objective. Outside areas it uses a 40mm marker, with inclusive 3-inch horizontal range measured from closest base/marker parts and 5-inch vertical range. Ambiguous overlapping areas require explicit mission selection; automatic linking fails transactionally. Markers are not movement obstacles.
- Objectives start uncontrolled. At phase/turn end, sum nonnegative eligible OC from every model in range, including zero contribution from shocked models. Higher totals control; equal totals are uncontrolled unless secured. Queries return the boundary snapshot rather than recomputing ownership after every move.
- Securing requires an explicit granting effect and currently controlled objective. Secured control survives absence and ties until the opponent has greater OC at **phase end**; a turn-end check alone does not revoke it. A unit controls an objective only if its army controls it, it is in range and it contains a model with positive OC.
- Core control awards no points automatically. The old four-marker, five-points-per-owned-marker Command scoring is an explicitly selected legacy mission fixture in `full_game.rl`; bare Board state defaults to no scoring. Objective IDs are used correctly for both armies. Legacy faction securing consumers use the shared core securing state, without claiming their old faction permissions are new-edition data.
