# Source instances, events and effects —17.E

Authority: core round/turn/phase boundaries pp.28–38, attack selection/targeting pp.16–19, shock pp.9/30, destruction p.87 and returning models p.88. The user supplied current-player then opponent sequencing, and appendix01.02.02/01.02.04 persisting effects/offboard policy. Source requirements and exact printed limits were audited in all67 Orks datasheets; for example Nazdreg has separate once-per-round/per-army and once-per-phase/per-army abilities, while Bomb Squigs combines once-per-turn and twice-per-battle/per-unit. This framework does not install those ability effects or unit profiles.

Source instances keep stable source unit/model identities, player, explicit rule code, event/phase/turn predicates, target scope and typed payload. Rule codes are supplied identities, not inferred from equal display names. Model sources follow current constituents through casualty compaction and bank transfers. Gameplay emits move-start/end, attack selection/targeting/end, shock-start/end and released destruction events, as well as phase/turn/round timing windows. Deferred attack deaths and Fight on Death retain their core release points; eligible source-only death observers cause retention too.

Legacy timing choices and source instances share each controller’s choice group. Source-only events also resolve turn-owner choices before opponent choices. Optional passes spend nothing; mandatory sources cannot be skipped. Pending handles are rechecked after each choice, so shared limits or a dead source can invalidate another pending entry. Source selectors are bounded numeric buttons, not UnitID/model/coordinate clicks. Names come from source metadata and MultipleChoises supplies explicit buttons. Rules.gd and TraceManager.gd remain unchanged.

Usage keys combine rule, player, army/unit/model scope and stable subject. All phase/turn/round/battle limits apply together; interval resets do not erase battle totals. Unlimited abilities do not accumulate meaningless bounded counters. CP spending remains the existing shared CP policy and actual card actions in their later batches; this event kernel does not make the40 configured Orks cards playable.

Typed numerical, incoming AP/D and named/profile/physical weapon-rule grants receive unique linear effect handles. Equal overlapping sources keep distinct lifetime/removal ownership. Default duration is the giving phase; explicit turn/round/next-own-turn/battle durations preserve granting-player ownership through reserves/passengers and source death where permitted. Phase-end expiry follows end effects/mission work and precedes turn-end windows. Removal reaches live models and casualty archives in every bank, preventing revival of expired grants. Unit-wide effects refresh returned constituents without duplicating surviving grants. Source prototypes remain unmodified when a tagged copy is installed.

Passive unit auras refresh live battlefield eligibility, unit keyword predicates and base range when movement/boundaries/destruction change state. They disappear on source death/disablement or recipient exit and reappear on entry; equal overlapping auras remain independent. Own units are in range of their own abilities. Offboard permissions never permit external distance/visibility measurements. The preserved circle/grid abstraction and unsupported hull/oval gates still apply. Model-specific aura range, wholly-within auras and future source-specific conditions/effect handlers require their printed source adapters; they are not silently inferred from this unit-aura mode.

Configured capacities are64 registered source instances,64 pending handles,64 active effects and64 usage keys. Stored instance references and effect handles are linear bounded integers; action source selectors independently enumerate64 choices. Effect handles are monotonic1–4096, so removal cannot redirect a later grant. Rule codes1–512 distinguish supplied abilities. Capacity overflow asserts rather than silently dropping effects; capacities must be rederived against playable legal army combinations as actual later source adapters/data land. Numeric/weapon modifiers retain their existing bounded list limits. These are supported implementation capacities, not tabletop limits.

Restore checks validate source/payload identities, owners/scopes/enums, use records and effect handles/recipients; forged modifier handles are rejected. Future Waaagh/riled conditions, attachments, reactive movement/shooting, hit/kill provenance, healing/revival and actual faction/card effects retain their later ROADMAP owners. Generic event fixtures do not certify those mechanics or all67 datasheets.

Shared17.D/E schemas are state/observation25, action15, next-state26. All new fields use generated lifecycle and standard bounded storage.
