# Movement and deployment — task 11

This report describes task 11's movement and setup implementation. ROADMAP.md records final validation and downstream obligations. Preserve the whole-inch quad grid and the user's terrain-area abstraction: no continuous positions, new physical terrain features or exact model-body visibility are introduced.

## Rules and implementation

Sources are [the procedural reference](11th-edition-core-rules-procedural.txt), especially pp.12–14,32–33,68–71,78–85,87, and [the supplied appendix](11th-edition-supplied-appendix.md), including Random Characteristics 02.02.03. The user subsequently requires uniform Scouts values; this overrides support for mixed Scouts combinations.

- **Mandatory selection (p.32):** select every friendly battlefield/reserve unit once during the Movement phase. Remain Stationary is explicit, including for reserves; ending the phase cannot bypass outstanding selections. Passengers and Disembark require task 16's transport model.
- **Stationary/Normal/Advance (p.33):** stationary changes no position or rotation and produces no actual-move timestamp. Normal and Advance require an unengaged unit and unengaged final placement. Each model spends its own M; Advance adds a complete D6 before paths and forbids charging/action starts for the rest of the turn. Existing ranged ASSAULT gating remains available; complete shooting modes belong to task 12.
- **Fall Back (pp.24/33):** Ordered Retreat is available only while unshocked; Desperate Escape is also available and required instead when shocked. Desperate Escape collects one hazard per model, uses the common mortal/FNP/destruction engine, allows enemy traversal and requires a post-move Battle-shock test when still unshocked. Both modes finish unengaged and forbid shooting, charging and action starts until turn end.
- **Individual paths (pp.12/87):** retain the existing rigid `move_to(BoardPosition)` convenience and offer independent model selection, multiple whole-grid waypoints, free circle rotation and explicit completion. All segments consume the selected model's budget. Intermediate incoherence is permitted; final coherency, support, no overlap and move-specific end restrictions are mandatory. Stage complete Unit value copies and commit only after final validation. Cancellation restores positions rather than leaving a partial move.
- **Flying/Hover (pp.71/82):** optional Take to the Skies reduces maximum distance by two unless the unit has Hover. Only FLY models receive enemy/terrain traversal and ignore vertical distance; non-FLY members retain ordinary traversal and the unit's distance penalty. Full Charge integration awaits task 13's charge workflow.
- **Super-heavy Walker (p.85):** normal/advance/fall-back grants non-TITANIC enemy traversal. It does not revoke general friendly traversal or Desperate Escape's independent enemy traversal. Optional MOBILE is applied temporarily and removed after the move; its end roll shocks on 1. Physical feature-height/Dense-feature movement remains deferred by the user's terrain instruction.
- **Deployment (pp.14/82):** every non-reserved unit must deploy; ordinary setup checks every base wholly in the configured legacy home zone. Infiltrators requires every live model to have the ability and strict horizontal clearance greater than eight inches from enemy models and the opposing home zone. Failed/cancelled setup retains the reserve entry.
- **Preset selection (pp.12/14):** search alternative column counts against all setup rules, not just battlefield bounds. Commit the exact validated formation. Mixed bases use each adjacent pair's required whole-grid spacing and per-row base sizes; a unique larger model must not force excessive spacing on smaller members. Presets remain a convenience and do not enumerate every possible tabletop formation. The user directs that units with no legal supported placement are destroyed instead of restarting deployment. Preserve their identities and destroyed models in the off-table archive; this is user-supplied simulation policy, not a claimed PDF rule.
- **Strategic reserves (p.68):** voluntary pre-battle selection requires explicit unit points and a configured battle points limit, excludes Fortifications and enforces the inclusive 50% cap. Legacy rosters have no supplied points; they cannot silently reserve everything by ending deployment early. Aircraft/passenger formation exceptions remain task 16.
- **Ingress/Deep Strike (pp.69/80):** ordinary arrival starts in round 2, places every base wholly within the union of six-inch edge strips, and stays strictly more than eight inches horizontally from all live enemies. Before round 3 no base may touch the opposing home zone. All-model Deep Strike replaces edge/zone placement, not timing or separation. Arrival locks other moves until the next Charge phase, while ordinary shooting/charge gates remain available unless a surviving same-turn Advance/Fall Back restriction forbids them.
- **Reposition/deadline (pp.68–69):** retire battlefield slots, transfer stable identities, archives and duration/history carriers once, and retain same-turn restrictions. Turn-long compatibility gates expire in reserves too. End round 3 archives never-arrived reserves, exempting repositioned units. Reject transfer of pending battlefield death hooks rather than stranding them outside the destruction resolver; full reactive/off-table integration needs later supplied rules.
- **Scouts (pp.78/84, user restriction):** all models must have the same Scouts value. Current dynamic model metadata uses an explicit assertion; constant datasheets must validate the assumption statically when introduced. Resolve optional pre-battle scout movement or reserve setup wholly in the home zone, with fixed Scouts distance and final strict horizontal separation greater than eight inches. Dedicated-transport alternatives await task 16.
- **Surge (pp.70/74):** a caller must supply an actual granting trigger/distance. Require live, unshocked, unengaged and not-moved-this-phase state, exclude Aircraft targets, and allow tied closest targets. Check reachable whole-grid endpoints through a finite visibility graph, preserving base clearance and segment lengths. Each model's approach obligation is evaluated with the other chosen final positions fixed; no coupled global rearrangement optimizer is claimed. Reject incidental engagement with other units. Generic completed moves also record the phase, preventing a later surge.

## Numeric state and action contracts

State/observation schemas are **10**, action schema **6**. Use bounded standard types for movement values, model data, points, Scouts and action parameters. Random M is encoded as `M+1` in bounded storage, with zero meaning no override; no negative generated type name or custom unbounded Quantity is introduced. Phase/entity references follow existing lifecycle metadata conventions and remain outside numeric tensor inference. Existing move booleans, move-kind enums and legal-action masks remain available.

Retain UnitID/ModelID wrappers and BoardPosition x/y. `select_moving_model` uses `board.moving_unit` for production model clicks. `waypoint` uses existing board-location controls. Rotation has finite degree inputs; the choice panel supplies quarter-turn buttons and the enumeration fallback exposes remaining degrees. Save-group/damage selector behavior remains intact.

Reserve-selection actions index `reserve_units`, not battlefield units: deployment, strategic-reserve selection, ingress and Scout reserve setup use named panel buttons; InteractionManager suppresses battlefield clicks for those actions. Boolean movement choices have contextual labels. Rules.gd and TraceManager.gd remain unchanged.

Persist explicit `frm Unit` value snapshots: inferring a snapshot from a ref-returning accessor can retain the wrong object across action suspension. Keep generated Unit initialization so every owning vector is initialized; an initializer that sets only new scalar fields is insufficient.
