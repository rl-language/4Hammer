## Generic actions

`action_start_valid` checks actual battlefield membership, ownership, living positive OC, AIRCRAFT/FORTIFICATION, Battle-shock, engagement (TITANIC exception), Advance/Fall Back, a previous action start this turn and the phase-local after-shooting restriction. All printed shooting types prohibit action starts after shooting (pp.34–35/57), including an activation with no weapons selected.

`begin_unit_action` records one start per turn and locks declaring a charge and ordinary non-TITANIC shooting until turn end. A later turn may start another action while an earlier one remains pending. `UnitActionProgress` records are bounded by the supported turn count and identified by a bounded start-turn stamp. A mission consumer retains that stamp and supplies its own STARTS, UNITS, USE LIMIT, COMPLETES, EFFECT and additional restrictions. The latest-action overload is a convenience; older pending actions must use the explicit stamp overload.

Non-exempt completed movement, including direct out-of-phase Move and charge movement, fails every unresolved action. Remain Stationary does not move; Pile In and consolidation are explicitly exempt. Repositioning/departure records failure before reserve transfer. Actual completion requires a surviving battlefield unit, no interruption and no current Battle-shock; recovering from earlier shock does not invent a permanent failure. Completing by stamp consumes only that action and returns whether its supplied mission effect should resolve. Failed/shocked completion triggers no effect. Invalid/duplicate completion cannot alias another action. Malformed bounded handles and contradictory completion state are rejected by save validation.

The book's DEPLOY DEVICE is explicitly an unusable illustration. No new playable mission action or marker effect is invented. Mission action selection/timing/effects and transport departure integration remain tasks 17 and 16 respectively.

## Editor, storage and geometry

State/observation schemas are **15**, action **11**. Rebuild native libraries, Rulebook headers and C++ bindings together; old saves, policies and catalogs are incompatible. Persisted grants, action status and decisions use Bool, enum or standard bounded integers; no stored Float/Quantity or manual partial init/drop is added.

Unit, model and location payloads retain their existing Godot discovery shapes. Explosives gets an explicit source button because ordinary shooting is simultaneously available through another UnitID selector. Smokescreen/Counteroffensive source buttons name the unit and cost. Epic/Explosives/Impact bearer clicks highlight the source through `board.moving_unit`; mortal/destruction clicks keep their existing target context. Rules.gd and TraceManager.gd remain unchanged.

Smokescreen uses the existing circular-base abstraction: a smoke base crossing a centre sight segment makes that target partially obscured. One obscured model means the unit is not fully visible. Direct SMOKE targets do not need this geometric test. This is a documented approximation, not certification of body/silhouette visibility; actual supplied geometry and rendered interaction remain task 17. Physical terrain features/continuous coordinates stay deferred by user instruction.
